# Local concert search

Add a search input to the user log, with an unchecked `Search setlists` checkbox beside it. Filter both chronological columns immediately using case- and accent-insensitive substring matching. Remove special characters from query and indexed text, retaining letters, numbers, and spaces; collapse repeated spaces and trim edges. Spaces remain meaningful: `AC/DC` matches `acdc`, while `Big Thief` does not match `bigthief`. Match any lineup artist regardless of personal attendance; when enabled, also match cached performance song titles and musical-program song titles. Never match Spotify Top 5, notes, URLs, stages, or venue metadata. Blank or punctuation-only queries restore the existing list. Missing song data does not suppress artist matches.

Keep hidden-only mode, chronological ordering, and current counts/hidden counts, with counts narrowed to search matches. Show `No matches` for a nonempty query with no results. Keep the compact dark styling and accessible input/checkbox labels; no search button, requests, database writes, URL navigation, or loading message.

Use a pure memoized index over the in-memory catalog. Bundle existing setlist and musical JSON through a shared static module; keep Spotify dynamically loaded only for song displays. This avoids fetching on typing/toggling and avoids a generated index that could fall out of sync when caches refresh. Static assets still load normally with the application, and the existing catalog subscription remains unchanged.

Tests must distinguish supporting acts and unselected festival sets, exact performance/concert identity, musical programs, Spotify exclusion, normalization, empty queries, and stale set/artist references. Verify desktop/mobile controls and filtering in the browser, run the project checks, then commit/push through the existing GitHub workflow.

Verified: 41 TypeScript tests and 21 cache tests passed, as did lint and build. Browser checks on the production-backed localhost log confirmed punctuated/mixed-case artist searches, accent-insensitive song searches gated by the checkbox, Spotify-only exclusion, hidden-only results, keyboard clearing, and the 390-wide mobile layout. Search only reads its index; it has no effect, fetch, Firestore query, dynamic import, or URL change. The search input uses a 1rem font to avoid automatic focus zoom on iPhone.
